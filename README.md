# 时宜 · 生活与健康手账

一个原生 HTML / CSS / JavaScript 的独立网页，用来安排每日作息，记录体检、洗牙等健康事项。数据保存在当前浏览器的 `localStorage`，无登录、无云同步、无应用后端。

## 启动

安装 Node.js 18 或更新版本，在 PowerShell 中运行：

```powershell
cd A:\explore\health_hub
npm start
```

打开 [http://127.0.0.1:4317](http://127.0.0.1:4317)。无需 `npm install`，没有第三方运行依赖。预览服务只监听本机地址，按 `Ctrl+C` 停止。

端口被占用时，可运行 `npm start -- --port 4318`。记录与网址的协议、域名和端口绑定；更换端口或改用 `localhost` 会看到独立的数据。长期使用建议固定同一网址。

也可以直接打开 `index.html`；不同浏览器对本地文件存储的处理可能不同，推荐使用上面的固定本机网址。

## 能做什么

- **今日概览**：只显示今天安排的作息，支持直接完成下一项、筛选未完成项和取消打卡；同步展示完成进度、最近 7 天的打卡次数及下次健康事项。当天已打卡的作息即使暂停或修改星期，也会保留到当天结束。
- **作息计划**：按时间管理安排，支持每天、工作日、周末或自选星期重复；可以暂停 / 恢复、新增、修改和删除。初始作息只是可编辑的起步计划；历史打卡按天保存，暂停不删除历史。
- **健康档案**：记录体检、口腔 / 洗牙、疫苗或其他事项的日期和备注，自行填写下次日期；支持搜索事项与备注，组合筛选类型和计划状态，并按记录日期或下次日期排序。无匹配结果时可一键清除筛选。
- **记录完成**：从已有的下次安排新增本次记录，保留原有历史，并清除旧记录上的计划日期。
- **备份**：导出 JSON；导入时先校验内容，再确认是否替换当前浏览器中的全部记录。

下次日期由你按实际安排或医嘱填写，网页不会推荐医学周期。日期接近或已到期时，仅在打开页面时显示提示；关闭页面后没有后台提醒。这里用于记录，不提供诊断或医疗建议。

## 界面与交互约定

- **视觉方向**：暖纸底色、深松绿墨色文字、沙色晨光高亮；同色系只用一种「动作色」（松绿）和一种「时间色」（沙金）。颜色、字号、圆角、阴影与缓动曲线都收在 `styles.css` 顶部的 `:root` 设计变量里，换主题只需改这一处。
- **可读性**：正文与次要文字在纸底上均达到 WCAG AA 的 4.5:1，按钮、输入框边界和打卡圆圈等界面元素达到 3:1；固定字号的说明文字也不会低于 4.5:1。修改颜色后请重新核对对比度。
- **动效**：视图切换、打卡圆圈、进度环、周柱与弹窗都有短过渡（约 0.2–0.8 秒），并在 `prefers-reduced-motion: reduce` 时全部关闭。
- **键盘与触控**：Tab 有清晰焦点环，Esc 关闭弹窗且焦点回到触发按钮；移动端主要按钮不小于 44×44 px，弹窗改为底部抽屉式。

## 数据留存

请定期导出备份，导入替换前也建议先导出当前数据。清理浏览器数据、更换浏览器或设备可能导致记录无法继续访问；无痕模式的数据通常在窗口关闭后清除。备份文件包含个人记录，请自行妥善保管。

本地数据损坏或浏览器阻止存储时，页面会显示错误，不会自动用默认数据覆盖原记录。可以导出原始数据，或导入有效备份恢复。

已有记录和旧版备份可以继续使用。缺少重复设置的旧作息默认按每天执行、未暂停；读取时不会自动改写原始数据，正常保存和导出时会带上新增设置。

## 项目文件

| 文件 | 用途 |
| --- | --- |
| `index.html` | 页面、导航和编辑表单 |
| `styles.css` | 桌面与移动端样式 |
| `app.js` | 作息、打卡、健康记录和备份交互 |
| `data.js` | 本地存储、数据校验、日期计算和星期匹配 |
| `favicon.svg` | 本地页面图标 |
| `preview.mjs` | 仅用于开发预览的静态文件服务器 |
| `data.test.cjs` | 日期和数据保存测试 |

运行 `npm test` 检查数据逻辑。

扩展作息设置时，沿用 `data.js` 中的校验与默认值规则；`days` 使用 `0`（周日）到 `6`（周六），`paused` 为布尔值。类型与图标展示集中在 `app.js` 的 `categories` / `recordTypes`，视觉变量集中在 `styles.css` 顶部。新增类型时需要同步修改数据白名单和表单选项。仍然使用原生页面与本机存储，无需增加框架或服务。

目前纯前端即可满足个人本机使用。以后确实需要多设备同步或跨设备提醒时，再考虑增加后端和相应的数据保护。
